## กฎเหล็ก — OMD เท่านั้น

งานนี้เป็นของแบรนด์ **OMD** ห้ามให้แตะลูกค้า TEPPEN ไม่ว่ากรณีใด (Gik ย้ำ 10 ก.ย. 2026)
ล็อกไว้ 4 ชั้นในระบบ ไม่ได้อาศัยความจำของคนเขียน query

| ชั้น | กันยังไง |
|---|---|
| แหล่งข้อมูล | `customers.brand = 'OMD'` และ `Customer."brandId"` = id ของ Brand code OMD |
| การล้าง tag | จำกัดเฉพาะแถวแบรนด์ OMD (เดิมกวาดทุกแบรนด์ — แก้แล้ว) |
| ตรวจก่อนจบ | ถ้ามีลูกค้าแบรนด์อื่นติด tag นี้แม้แต่คนเดียว ฟังก์ชัน `raise exception` ล้มทั้ง transaction |
| ช่องทางส่ง | Automation `brandCode = 'OMD'` → ใช้ `LINE_CHANNEL_ACCESS_TOKEN__OMD` คนละ OA กับ TEPPEN |

ตรวจแล้ว 10 ก.ย. 2026: ติด tag 1,878 คน **เป็น OMD ทั้งหมด** และไม่มี `lineUserId`
ตัวไหนซ้ำข้ามแบรนด์เลย (สอง LINE OA แยกกัน id จึงชนกันไม่ได้อยู่แล้ว)

คำสั่งตรวจซ้ำเมื่อไหร่ก็ได้

```sql
select b.code, count(*) from "Customer" c join "Brand" b on b.id = c."brandId"
where c.tags && array['points:OMD:near200','points:OMD:near200_active90']
group by b.code;   -- ต้องมีแถวเดียวคือ OMD
```

## ทำไมต้อง 200 แต้ม

| ข้อมูล 12 เดือนล่าสุด (OMD) | ตัวเลข |
|---|---|
| การแลกแต้มทั้งหมด | ~840 ครั้ง |
| แลกที่ 200 แต้มพอดี | **765 ครั้ง (91%)** |
| อัตราได้แต้ม | 10 บาท = 1 แต้ม |
| บิลเฉลี่ย | 588 บาท ≈ 58 แต้ม/มื้อ |

200 คือขั้นบันไดจริงของแบรนด์ ไม่ใช่ตัวเลขที่ตั้งขึ้นเอง
คนที่ค้างอยู่ 150–199 คือคนที่ "อีกมื้อเดียวก็ถึง" — ต้นทุนการกระตุ้นต่ำที่สุดในฐาน

## ของรางวัลที่ 200 แต้ม

**Omakase Don** (Gik ยืนยัน 10 ก.ย. 2026) ใส่ไว้ 3 จุดในการ์ด: บรรทัดแจ้งเตือนบนหน้าล็อก
หัวการ์ด และบรรทัดกลางใต้ตัวเลขแต้ม — คนเห็นชื่อเมนูตั้งแต่ยังไม่เปิดแชท

ถ้าเปลี่ยนของรางวัล แก้ที่ `omd_points_near200_seed.sql` แล้วรันซ้ำ คนที่ยังไม่ได้รับ
จะได้เวอร์ชันใหม่ในรอบถัดไป ที่ส่งไปแล้วแก้ไม่ได้

## การใช้งานประจำ

รีเฟรชรายวันทำงานเองผ่าน pg_cron ไม่ต้องรันมือ ที่เหลือคือ

```sql
-- ดูว่างานรายวันยังตั้งอยู่ และรอบล่าสุดผลเป็นอะไร
select * from cron.job;
select jobid, status, start_time, return_message
from cron.job_run_details order by start_time desc limit 5;

-- เร่งเคลียร์ backlog เร็วกว่าเพดานปกติ
select * from public.refresh_omd_point_messages(1000);

-- หยุดส่ง
select cron.unschedule('omd-near200-refresh');
update "Automation" set status = 'PAUSED' where id = 'auto_points_near200_omd';
```

แก้ข้อความ / เงื่อนไข Segment / cap → แก้ `omd_points_near200_seed.sql` แล้วรันซ้ำ
(ทุก statement เป็น upsert รันซ้ำได้ไม่พัง)

**ปิดไว้ถาวรแล้ว** — Gik ยืนยัน 15 ต.ค. 2026 ว่า **ไม่มีของรางวัลที่ 100 แต้ม**
(การแลกที่ 100 แต้ม 19 ครั้งในข้อมูลเก่าไม่ใช่รางวัลประจำ) ไม่มีข้อความไหนที่ส่ง

**กันคนเดียวได้สองข้อความ**: ฟังก์ชันรายวันตัวเดียวไล่ตามลำดับความสำคัญ

บิลเฉลี่ย OMD 588 บาท แปลว่าต้องมา ~3.4 ครั้งโดยไม่ได้อะไรเลยระหว่างทาง

**ข้อเสนอให้พิจารณา (ต้องคุยกับ Finance เรื่องต้นทุนต่อหน่วย)**: เพิ่มขั้นล่าง
เช่น 100 แต้ม = เครื่องดื่ม/ของหวาน จะทำให้ 1,729 คนที่ถือ 100–199 แต้มและ
ใกล้หมดอายุกลายเป็นกลุ่มที่คุยได้ทันที

**ความเสี่ยงที่ต้องชั่งด้วย**: ขั้นล่างที่ถูกเกินไปอาจกิน 200 แต้ม — คนแลกที่ 100
แล้วไม่สะสมต่อ เป้าหมาย 2,000 บาทต่อรอบจะหายไป ถ้าทำควรทดลองกับกลุ่มเล็กก่อน
