# OMD · แจ้งเตือน "ใกล้ครบ 200 แต้ม"

ตั้งไว้ใน CDP (Supabase `teppen-cdp`) แล้ว สถานะ **DRAFT — ยังไม่ส่งอะไรออกไป**
รอคนอนุมัติเปลี่ยนเป็น ACTIVE ในหน้า CDP

## ทำไมต้อง 200 แต้ม

| ข้อมูล 12 เดือนล่าสุด (OMD) | ตัวเลข |
|---|---|
| การแลกแต้มทั้งหมด | ~840 ครั้ง |
| แลกที่ 200 แต้มพอดี | **765 ครั้ง (91%)** |
| อัตราได้แต้ม | 10 บาท = 1 แต้ม |
| บิลเฉลี่ย | 588 บาท ≈ 58 แต้ม/มื้อ |

200 คือขั้นบันไดจริงของแบรนด์ ไม่ใช่ตัวเลขที่ตั้งขึ้นเอง
คนที่ค้างอยู่ 150–199 คือคนที่ "อีกมื้อเดียวก็ถึง" — ต้นทุนการกระตุ้นต่ำที่สุดในฐาน

## ก่อนกด ACTIVE — เคลียร์ 1 เรื่อง

ข้อความตอนนี้เขียนว่า "แลกรับ**ของรางวัลสมาชิก 1 สิทธิ์**" เพราะในระบบไม่มีข้อมูลว่า
200 แต้มแลกอะไรได้จริง ถ้าใส่ชื่อของจริงได้ (เช่น ของหวาน / เครื่องดื่ม) อัตราการกลับมา
จะดีกว่าคำกลาง ๆ มาก — แก้ที่ `omd_points_near200_seed.sql` แล้วรันซ้ำ

## การใช้งานประจำ

psql "$CDP_DATABASE_URL" -f web/sql/cdp/omd_points_near200_tags.sql

## วัดผลยังไง (30 วันหลัง ACTIVE)

เทียบ TEST_B (1,659 คน) กับ CONTROL (223 คน) ในตาราง `ab_test_membership`
ชื่อเทส `points_near200_OMD` ตัวเลขที่ต้องดู 3 ตัว:

1. **% ที่กลับมาใน 30 วัน** — ตัวชี้ขาด ต่างกันเท่าไหร่คือผลของข้อความล้วน ๆ
2. **% ที่แลกแต้มครบ 200** — บอกว่าข้อความพาไปถึงปลายทางจริงไหม
3. **ยอดใช้จ่ายเฉลี่ยต่อคน** — ระวัง cannibalization: ถ้าคนกลับมาแต่บิลเล็กลง แปลว่ามาแค่แลกของ

ถ้า lift ของข้อ 1 ต่ำกว่า 3 จุด ให้แก้ข้อความก่อน อย่าเพิ่งขยายกลุ่ม

## ก้าวถัดไปที่ยังไม่ได้ทำ

- **แต้มใกล้หมดอายุ** — ในกลุ่มนี้มี 621 คนที่แต้มจะหมดอายุใน 90 วัน
  "แต้มคุณจะหมดอายุ" แรงกว่า "อีกนิดเดียวก็ครบ" แต่ต้องมีตัวแปรวันหมดอายุในเทมเพลตก่อน
- **กลุ่มหายเกิน 90 วัน (978 คน)** — ใช้แต้มค้างเป็นเหตุผลกลับมา แต่ต้องเขียนคนละโทน
